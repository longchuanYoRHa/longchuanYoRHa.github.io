AERO60492 Coursework 3: UAV Feedback Control Under Wind Disturbance

Project Overview

Project explanation video

This project focused on developing an advanced feedback controller for UAV position stabilisation under dynamic wind disturbance using the provided PyBullet-based DJI Tello simulation environment. The coursework required designing an outer-loop controller that receives UAV position and attitude feedback and outputs velocity and yaw-rate commands. :contentReference[oaicite:0]{index=0}

The primary challenge was that the provided Tello stack already contains an internal cascade velocity–attitude–rate controller. Therefore, the outer controller does not interact with an ideal integrator, but instead with a slow and delayed closed-loop plant. This significantly affects controller stability, tuning difficulty, and wind rejection capability.

The final solution combined:

  • Inner-loop system identification
  • Cascade PID outer-loop control
  • Velocity estimation from finite differencing
  • Disturbance-rejection compensation
  • Bayesian optimisation-based automatic tuning
  • Experimental comparison between simulation and real UAV deployment

Understanding the Provided Tello Inner Loop

Identified inner-loop velocity response characteristics

The provided simulator already contains a complete Tello control stack:

  • Velocity PID loop
  • Attitude PID loop
  • Angular-rate PID loop
  • Motor mixing and thrust allocation

implemented inside TelloController. :contentReference[oaicite:1]{index=1}

This means the coursework controller only acts as a high-level outer loop generating velocity commands.

To properly design the outer controller, the inner-loop dynamics were first identified experimentally using direct command injection into the Tello stack. A dedicated identification script was developed to fit transfer functions for:

  • vx
  • vy
  • vz
  • yaw_rate

using first-order, second-order, and second-order-plus-zero models. :contentReference[oaicite:2]{index=2}

Inner-Loop Identification Results

The identified horizontal velocity dynamics exhibited:

Channel Model Bandwidth Overshoot Delay
vx / vy Second-order + zero + delay ≈0.25 Hz 22.8% 115 ms
vz First-order ≈0.96 Hz Minimal 56 ms
yaw_rate Second-order ≈9.68 Hz 56% ≈0 ms

:contentReference[oaicite:3]{index=3}

The key observation is that the horizontal channels are extremely slow and lightly damped compared to the vertical and yaw dynamics. This makes direct position control unstable if aggressive gains are used.

The identified system can be approximated as:

  • horizontal axes → second-order + zero + delay system
  • vertical axis → first-order system
  • yaw → fast second-order system

This justified the use of a cascade control structure and conservative bandwidth separation.

Outer-Loop Controller Design

Cascade outer-loop controller with disturbance rejection

The final controller uses a cascade PID structure:

Layer 1 — Position Loop

Position error is converted into a desired velocity setpoint in the world frame.

Layer 2 — Velocity Loop

Velocity error is regulated in the body-yaw frame using estimated velocity derived from position differencing between controller calls.

Layer 3 — Yaw Loop

Yaw angle error generates yaw-rate commands.

The implemented controller architecture is shown directly in the submitted controller.py. :contentReference[oaicite:4]{index=4}

The controller also includes:

  • Integral anti-windup
  • Velocity saturation
  • Coordinate-frame transformation
  • Body-frame velocity estimation
  • Persistent-state memory between calls

The final implementation was specifically designed around the identified low-bandwidth horizontal dynamics. :contentReference[oaicite:5]{index=5}

Disturbance Rejection Strategy

The simulator includes a dynamic wind model containing:

  • slowly varying steady-state wind
  • random gust disturbances
  • continuously changing wind direction

implemented inside wind.py. :contentReference[oaicite:6]{index=6}

Instead of implementing a full model-based disturbance observer, the controller uses:

  • integral action in both loops
  • velocity mismatch compensation
  • estimated disturbance accumulation

to reject persistent disturbances.

This acts as a lightweight disturbance-observer-based compensation structure while remaining computationally simple and compatible with the coursework interface constraints.

The disturbance-rejection structure significantly reduced:

  • steady-state drift
  • low-frequency wind bias
  • recovery time after gust disturbance

particularly in the horizontal axes.

Bayesian Optimisation Tuning

Manual tuning proved insufficient due to the large number of coupled gains and the stochastic wind environment.

Therefore, controller tuning was formulated as a high-dimensional optimisation problem using:

  • Gaussian Process Regression (GPR)
  • Latin Hypercube Sampling
  • Expected Improvement acquisition
  • staged cascade tuning

The optimisation process tuned:

  • outer-loop position gains
  • velocity-loop gains
  • yaw-loop gains
  • saturation limits
  • integral limits

against a cost function designed around the coursework marking criteria.

The cost function penalised:

  • slow convergence
  • overshoot
  • oscillation
  • velocity jerk
  • steady-state error
  • threshold violations

Targets were regenerated continuously during optimisation to avoid overfitting to a fixed waypoint set.

Simulation Environment

The simulation environment was implemented in PyBullet and includes:

  • UAV rigid-body physics
  • aerodynamic drag
  • motor lag model
  • dynamic wind disturbance
  • waypoint switching
  • live wind visualisation

The simulator executes physics at:

  • 240 Hz physical timestep

while the outer controller operates at:

  • 50 Hz position-control frequency

implemented in run.py. :contentReference[oaicite:9]{index=9}

A major discovery during the project was that:

  • the physical simulation step runs at 1/240 s
  • but the motor model and controller use 1/1000 s timing internally

which effectively slows the inner-loop response by approximately 4×. :contentReference[oaicite:10]{index=10}

This timing mismatch strongly influenced achievable outer-loop bandwidth and disturbance rejection performance.

Real Tello Experiment

Real Tello Experiment

The controller was also deployed onto a real DJI Tello platform using external motion-capture feedback.

Although the simulator and real UAV shared the same interface, their dynamics differed substantially. :contentReference[oaicite:11]{index=11}

Several factors contributed to simulation–reality mismatch:

  • real motor and battery limitations
  • communication delay
  • Vicon timing jitter
  • noisy localisation feedback
  • reduced safe velocity limits
  • target switching at fixed intervals
  • aerodynamic effects absent from simulation

The experiment therefore demonstrated not only controller performance, but also the practical limitations of transferring a simulation-tuned controller directly onto real hardware.

Technical Highlights

  • Platform: DJI Tello + PyBullet simulation
  • Control architecture: Cascade PID + disturbance rejection
  • System identification: transfer-function fitting + chirp validation
  • Tuning: Bayesian optimisation with GPR surrogate model
  • Simulation: PyBullet + dynamic wind model
  • Programming language: Python
  • Methods used: coordinate transforms, velocity estimation, automated tuning
  • Advanced features: cascade control, disturbance rejection, automated optimisation

Key Lessons Learned

This project highlighted the importance of:

  • understanding the true plant dynamics before tuning controllers
  • separating time scales in cascade control systems
  • designing controllers around bandwidth limitations
  • considering model mismatch between simulation and reality
  • using automated optimisation for high-dimensional tuning problems

The project also reinforced that robust UAV control is fundamentally constrained by:

  • actuator delay
  • inner-loop bandwidth
  • sensing quality
  • update frequency
  • disturbance estimation accuracy

rather than simply increasing controller gains.

“A stable UAV controller is not built by aggressive gains, but by respecting the dynamics hidden underneath the interface.”
